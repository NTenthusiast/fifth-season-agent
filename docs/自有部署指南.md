# 「第五季·续种」自有部署指南

> 适用场景：扣子（Coze）平台积分到期 / 停止托管后，把本服务完整迁到自己的服务器（校内主机、云主机、实验室机器均可）继续运行。
> 结论先行：**项目代码零平台锁定，模型调用走 OpenAI 兼容接口，换一个 API Key 就能跑。**

---

## 一、先弄清楚：什么在消耗扣子积分？

| 模块 | 是否消耗平台积分 | 说明 |
|---|---|---|
| **与知颜对话**（LLM 推理） | ✅ 消耗 | 每条消息经平台网关调用 doubao 模型，按 token 计费 |
| 注册 / 登录 / 投票 / 种子卡 / 组队 / 留言 / 风云榜 / 故事墙浏览 | ❌ 不消耗 | 纯 Supabase 数据库读写，不走大模型 |
| 托付书 / 海报图片生成 | ❌ 不消耗 | Pillow 服务端本地渲染，非生成式模型 |
| 网页静态资源 | ❌ 不消耗 | 纯 HTML/CSS/JS 文件 |

也就是说：**只有"对话"这一个功能依赖平台积分**，其余功能都是数据库与本地计算。积分停止后，最先失效的只是知颜的"大脑"。

## 二、平台依赖清单（迁移时只需替换这 3 处）

| 依赖 | 环境变量 | 自部署替代方案 |
|---|---|---|
| ① 大模型网关 | `COZE_WORKLOAD_IDENTITY_API_KEY` / `COZE_INTEGRATION_MODEL_BASE_URL` | 自有 API Key（见第三节，代码已支持回退 `FS_LLM_API_KEY` / `FS_LLM_BASE_URL` 或标准 `OPENAI_API_KEY` / `OPENAI_BASE_URL`） |
| ② Supabase 数据库 | `COZE_SUPABASE_URL` / `COZE_SUPABASE_ANON_KEY` / `COZE_SUPABASE_SERVICE_ROLE_KEY` | 自建 Supabase 项目（有免费额度）或任何 PostgreSQL；代码已支持 `.env` 文件加载 |
| ③ 对象存储（托付书/海报产物） | `COZE_BUCKET_NAME` / `COZE_BUCKET_ENDPOINT_URL` | **可不配**：无桶配置时自动落到本地 `assets/web/uploads/`，经 `/static/uploads/` 直链访问 |

除以上 3 处外，其余全部本地化：`coze_coding_utils` 框架包在项目 venv 内、前端纯静态、图像渲染用 Pillow + 内嵌字体。

## 三、迁移三步走

### 第 1 步：带走代码与数据

```bash
# 1. 整个项目目录拷走（含 uv.lock，依赖版本锁定）
# 2. 数据库导出：Supabase Dashboard → Database → Backups，
#    或用 SQL 编辑器逐表导出（fs_users / fs_projects / fs_teams 等 14 张业务表 + memory 线程表）
```

### 第 2 步：配置环境变量

在项目根目录建 `.env` 文件（supabase_client.py 已内置 load_dotenv，会优先读取）：

```ini
# —— 模型（三选一，任一 OpenAI 兼容端点均可）——
# 方案 A：火山方舟直连（延续现有 doubao 体验，个人充值即可）
FS_LLM_API_KEY=你的方舟APIKey
FS_LLM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3

# 方案 B：DeepSeek（便宜量大）
# FS_LLM_API_KEY=sk-xxx
# FS_LLM_BASE_URL=https://api.deepseek.com/v1

# 方案 C：任何 OPENAI_API_KEY 兼容服务（也识别标准变量名）

# —— 数据库（自建 Supabase 或兼容 PostgreSQL）——
COZE_SUPABASE_URL=https://你的项目.supabase.co
COZE_SUPABASE_ANON_KEY=你的anon-key
COZE_SUPABASE_SERVICE_ROLE_KEY=你的service-role-key

# —— 对象存储（可选，不配则自动本地存档）——
# COZE_BUCKET_NAME=xxx
# COZE_BUCKET_ENDPOINT_URL=xxx
```

> 模型名在 `config/agent_llm_config.json` 的 `config.model` 字段，换成你实际开通的模型 ID 即可（如方舟的 `doubao-seed-2-0-lite-xxx` 或 DeepSeek 的 `deepseek-chat`）。系统提示词（sp）与 35 个工具无需任何改动。

### 第 3 步：安装依赖并启动

```bash
cd 项目目录
uv sync                 # 按 uv.lock 精确还原依赖
python3 src/main.py     # 默认 5000 端口；自定义：python3 src/main.py -p 8080
```

浏览器访问 `http://服务器IP:5000` 即是完整站点（介绍页 + 对话页 + 全部功能）。

## 四、常见问题

**Q：换模型后知颜的"人格"会变吗？**
系统提示词（6400 字四季人格 SOP）在 `config/agent_llm_config.json`，与模型解耦；换同档位模型（doubao / deepseek-chat）人格与工具路由基本一致，个别语气差异属正常。

**Q：历史对话记忆还在吗？**
记忆存在数据库 `memory.checkpoints` 表，随数据迁移一起走，不绑定平台。

**Q：只想要网页展示（不跑对话）可行吗？**
可行。`assets/web/` 是纯静态目录，介绍页（档案墙 / 故事墙 / 规则页等静态部分）可直接丢给任何静态托管（GitHub Pages / 校内 nginx）；但投票、种子卡等动态功能需要后端在跑。

**Q：成本大概多少？**
- 服务器：最低 2C4G 即可（实测对话链路内存占用 < 1.5G）
- 模型：deepseek-chat 约百万 token 数元级；按每条消息平均 3 次工具轮次估算，一个学期校级使用量在数十元以内
- Supabase 免费层（500MB）对本站 14 张表的体量绰绰有余

## 五、验证自部署是否成功

启动后依次检查：

```bash
curl http://localhost:5000/api/health        # 服务存活
curl http://localhost:5000/api/stories       # 数据库连通（应返回故事列表）
curl http://localhost:5000/api/dormant       # 候选池数据
```

再打开网页发一条消息——知颜正常回复即代表模型链路迁移成功。
