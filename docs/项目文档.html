一句话概括

校园里每年都有大量因毕业、换届、时间不足而暂停的好项目。它们大多不是失败了，只是没人接得住。 「第五季·续种」用 AI 智能体接管这些项目的传承生命周期——从建档、组队、沉淀成交接包，到休眠归档， 再到被下一位同学唤醒接棒。

一项目背景与用户痛点

高校里最被浪费的资源，不是经费，也不是场地，而是「已经有人做过一半的事」。

1.1 一个普遍但少被正视的现象

几乎每所高校都存在这样一批项目：支教队、无障碍调研、校园手绘地图、公益义卖、社团品牌活动。 它们有的做得相当扎实——有调研报告、有原型、有合作渠道——却在某一年突然停住， 原因往往朴素得令人无奈：发起人毕业了、负责人换届了、 核心成员课业冲突。

项目停下的那一刻，最可惜的不是没做完，而是已经付出的经验随人一起离场： 踩过的坑没人知道，谈好的渠道断在私人微信里，调研数据存在某台已经格式化了的电脑上。 于是下一届同学想做同一件事时，几乎必然从零再来一遍——重复调研、重复踩坑、重复失败。

1.2 三类核心痛点

角色 痛点 现状
即将离场的人
毕业生 / 换届负责人		 手上有做了一半的项目，想交给别人却无从下手——没有交接标准，也找不到合适的人。 要么草草解散，要么把资料打包丢进群里，此后无人问津。

团委 / 指导老师		 想了解哪些议题被反复提出却始终没做成，缺少可依据的数据。 依赖零散汇报与个人印象，难以看清全局。

1.3 已有做法的局限

  • 网盘 / 群文件归档——只存了文件，没有存"为什么这么做""哪里踩过坑"，接手者仍要重新理解一遍。
  • 社团内部老带新——依赖个人意愿与师徒关系，一旦断代即彻底失传。
  • 通用项目管理工具——面向"进行中"的项目，不处理"暂停后如何被重新启动"这一根本问题。

换言之，现有工具解决的是项目在执行时怎么管，而没有人解决 项目停下之后怎么活下来。这正是本项目的切入点。

二项目目标与核心功能

2.1 核心命题

让 AI 智能体「知颜」接管校园项目的传承生命周期，使每一份被时间搁置的校园善意与创意， 都能等到接过它的人。

我们不试图让 AI 替人做项目，也不替人创造意义。智能体只做一件事： 把"人走事散"变成"人走事留"。

2.2 底层模型：四季轮回 + 第五季

系统用一套原创的四季状态机描述项目的一生，并用「第五季」表示循环的重新开始—— 这是整个产品的概念基石，也是所有数据字段与交互设计的依据。

2.3 功能地图

A. 四季之旅——传承生命周期主干

  1. 春·萌芽 · 建档与种子卡——对话即建档；碎片想法被提炼为结构化「种子卡」（标题 / 简介 / 领域标签 / 所需能力）。
  2. 夏·生长 · 组队与执行——按能力互补推荐队友，成员入组采用申请—审批制；进展记录为动态时间线。
  3. 秋·沉淀 · 交接包——AI 通读全部动态，提炼五件套：已有成果 / 执行经验 / 踩过的坑 / 遗留问题 / 可复用资源。
  4. 冬·蛰伏 · 休眠归档——项目连同经验一起封存，进入唤醒候选池，学生可为其投票。
  5. 第五季 · 唤醒接棒——按「这颗种子的故事 → 为什么是你 → 接手第一步」三层叙事匹配接棒人；匹配采用六维可解释评分（技能互补 40 / 兴趣与议题 25 / 年级阶梯 10 / 传承准备度 10 / 社交邻近 8 / 时间投入 7），接棒须走三步确认：接棒意愿 → 原负责人核验授权范围与资源有效期 → 双方确认后正式唤醒。

B. 传承宝库——让传承被看见

C. 个人板块

档案画像、待办管理、灵感库，以及面向学校与社团的校园议题洞察—— 聚合全库数据，找出「被反复提出却始终无人完成」的议题，生成传承报告。

D. 需求推理与成长规划

用户只需像聊天一样描述自己——「我会一点设计和摄影，课余时间不多」—— 知颜便会展开三段式推理：先盘点你的能力与约束，再映射到校园里真实存在的需求缺口， 最后给出按匹配度排序的项目推荐（每项附匹配理由与预计投入）。 确定方向后，她还会给出分阶段的成长规划：目标拆解、时间预估、 每阶段可验收的小成果、本周就能做的第一步，以及可能的风险提醒。

智能体的能力边界由 37 个工具定义，覆盖个人档案、项目生命周期、传承扩展、种子卡生态、协作沟通与个人项目库。

工程要点一：防止工具误选

37 个工具中存在语义相近的组合（如「看有哪些项目」与「把想法立成项目」、 「看某个项目资料」与「看全校哪些项目需关注」）。系统在提示词高权重位置内置一张工具路由表， 逐一映射用户意图到目标工具，并为易混工具在函数文档中补充「不适用场景」说明——这是让工具选择准确率显著提升的关键改动。

工程要点二：成员入组必须走审批

直接写入成员关系会绕过发起人。系统在提示词层设强制约束：申请入组时严禁调用 add_project_member，只能以项目动态形式留下申请记录，待发起人确认后方可入组。 提示词与工具实现双重约束，保证协作秩序不被 AI "代劳"破坏。

工程要点三：滑动窗口不切断工具调用配对

为控制上下文长度，会话只保留最近 40 条消息。但朴素截断会把 AIMessage(tool_calls) 与其对应的 ToolMessage 拆散，导致上游网关直接返回 400 错误。 系统在截断后额外检测窗口首部是否存在孤立工具结果并整体丢弃，落到安全边界—— 这类问题在演示中途出现会直接中断对话，属于必须消除的稳定性隐患。

3.3 数据模型：20 张业务表

当前源码实际引用 20 张 fs_ 业务表，覆盖项目、传承痕迹、协作团队、站内消息、个人项目和档案故事： 项目本身、项目成员、项目动态、交接包、唤醒记录构成传承主链； 故事卡、成就、投票、匹配日志构成可观测层；真实案例库则把全国高校已落地的项目经验引入对话，作为推荐时的「外部参照系」。完整字段见附录。

3.4 工程化与稳定性

  • 数据库故障四层容错——HTTP 传输层对 502/503/504 自动重试；工具层异常兜底； 会话层降级为无记忆模式继续对话；前端提示稍后自动重试。
  • 双库隔离——开发库与生产库完全隔离，生产环境数据仅可经受控通道写入，避免误操作污染。
  • 客户端复用——数据库客户端全局缓存复用，避免同一请求内反复建立连接。
  • 服务端渲染——托付书与海报由 Pillow 在服务端合成中文字体排版，不依赖前端环境。

四项目创新点

4.1 概念创新：把「失败项目」重新定义为「休眠种子」

这是本项目最根本的一步。在既有语境里，一个停掉的项目等于一次失败，参与者容易背上心理负担，旁观者也不会去看第二眼。 我们把状态从「终止」重新定义为「休眠」——它不是结束，而是在等待下一双手。 这个重新定义不是文案包装，而是贯穿到数据模型的实际设计： 休眠项目保留全部档案、可被检索、可被投票、有明确的唤醒路径与优先级排序。

4.2 机制创新：交接包五件套 + 三层唤醒叙事

交接包五件套把「人走事散」中最容易丢失的部分显式结构化：已有成果、执行经验、踩过的坑、 遗留问题、可复用资源。其中「踩过的坑」与「遗留问题」是常规项目文档很少记录、却对接手者价值最高的两类信息。

三层唤醒叙事则解决了「推荐项目」这类功能常见的空洞感。系统不泛泛推荐， 而是按固定结构呈现：这颗种子的故事（它从哪来、沉睡了多久）→ 为什么是你（你的能力与它的缺口如何对上）→ 接手第一步（具体该先做什么）。 让被搁置的项目被重新"看见"，而不只是被列在清单里。

4.3 角色创新：AI 不做决策者，做传承的守护者

系统在提示词中明确划定边界：不替任何人创造意义，也不把项目包装成它没有的样子。 唤醒时只讲旧团队真实留下的东西，不添油加醋；成就不可能被单独发放，只能由真实行为触发。 AI 在这里的位置是记录者与牵线者，而不是替用户判断"这个项目值不值得做"。

4.4 交互创新：把生命周期做成可感知的四季

大多数管理类产品的状态是抽象的（进行中 / 已暂停 / 已归档）。本项目用四季作为状态语言， 并让每个季节在界面上拥有独立的视觉与叙事—— 用户不需要理解"状态机"，也能直觉地知道自己处在项目的哪一段、下一步该做什么。

4.5 数据创新：让传承本身成为可观测对象

系统不止管理项目，也度量传承：全校技能供需图谱回答"校园缺什么能力"； 需求投票回答"哪些休眠项目最该被唤醒"；议题洞察回答"哪些事被反复提出却始终没人做成"； 传承者成就与故事墙让每一次接力都留下痕迹。这些数据此前在校园里没有任何地方被系统性地收集过。

4.6 知识创新：真实案例库——让新人站到「前人的肩膀」上

「从零再来」的另一半原因是不知道同类事已被做成过。系统内置一个 真实案例参考库：收录蓝信封留守儿童书信陪伴（17 年、210 万封信、1478 所乡村学校）、 南京大学「雪域寻音」口述历史（第十九届挑战杯特等奖）、高校旧衣回收、朋辈心理互助等 14 个全国高校已落地的项目，每条均带可跳转的官网链接与真实成果数据。 当用户描述自己的需求时，知颜检索同类案例，把「别人做成的样子」直接呈现在对话里—— 推荐不再只是匹配，而是有据可依的借鉴。

4.7 交互创新：显式推理链 + 有温度的人格

推理可见：知颜的推荐不黑箱。用户描述需求后，她会显式展开三段式推理—— 能力盘点 → 需求映射 → 匹配推荐，每项推荐附带匹配度评分与理由（如「95 分：完全匹配你的摄影能力， 每周 2-3 小时即可参与」），并落到分阶段规划：第一步做什么、每阶段验收什么、风险在哪。 人格可信：知颜被塑造为一位温柔细腻、记得住细节的学姐—— 会记住用户的年级与能力，主动替用户想到时间约束；语气克制而真实， 但所有温度都来自措辞而非表情符号，杜绝「客服式空洞热情」。 温柔的表达与严谨的推理并存，是本项目在对话体验上刻意打磨的平衡点。

4.8 机制创新：六维可解释匹配 + 接续治理闭环（v6.0）

匹配不再是黑箱：接棒推荐采用六维评分并逐维披露证据——技能互补（命中了哪些能力、 还缺什么）、兴趣与议题、年级阶梯（在校时间窗口：大一 10 分、研三 2 分，临近毕业自动降档并提示组队）、 传承准备度、社交邻近（与原团队领域交集）、时间投入（档案中声明的每周小时数）。 未知维度不臆测补分：档案缺失的维度显式标注"未知"，不虚构证据。 推荐分不自动放行：接棒须走三步确认（接棒意愿 → 原负责人核验授权 → 双方确认）， 且交接包须通过 100 分接续准备度评估（五件套 50 + 过程动态 20 + 授权 / 资源有效期 / 原团队权益声明各 10）方可正式唤醒。 首页「验证中心」与「交接包实探」区块将试点实录、六维拆解与交接包原文直接开放给每一位访问者核验—— 我们展示的不是介绍，是可点开的实物。

五应用场景与效果验证

5.1 典型应用场景

场景一 · 毕业季的项目托付

一位大四同学手上有一个做了两年的校园无障碍调研项目，只完成了两栋教学楼，即将毕业。 他与知颜对话完成沉淀：系统通读全部项目动态，提炼出交接包——成果是"两栋教学楼的完整测绘与调研报告"， 踩过的坑是"物业协调需提前两周预约"，遗留问题是"其余五栋楼数据未采集"， 可复用资源是"已谈妥的指导老师与测量工具清单"。随后项目转入休眠， 并生成一张带寄语的项目托付书，可直接分享给潜在接棒人。

场景二 · 新生的第一次接棒

一位大二同学对知颜说"我会一点前端，想做点对校园有用的事"。系统不抛清单， 而是检索休眠项目后给出三层叙事：这颗种子三年前由谁发起、只做到哪一步就停了； 你的前端能力正好接上它缺的那一环；建议你先花一周读完旧团队的调研与原型， 再把剩下几栋楼的数据补齐。确认接棒后，项目进入第五季·重生，负责人正式变更， 传承故事卡自动挂上故事墙。

场景三 · 面向学校管理者的议题洞察

团委老师询问"哪些事同学们反复想做却一直没做成"。系统聚合全库领域标签与阶段分布， 输出议题传承报告：指出哪些议题被多次提出（如"校园无障碍""旧物循环"）， 其中多少仍处于休眠或未推进状态，并就每个议题给出最值得被接棒的方向。

六项目价值与未来展望

6.1 项目价值

对学生的价值

让想做事的人不必从零开始。前人踩过的坑、谈妥的资源、留下的数据，都成为后来者的起点—— 这既降低了尝试门槛，也让「半途而废」不再是一种羞耻。

对学校的价值

把散落在个人手中的项目经验，沉淀为可检索、可传承的校园公共记忆。 学校首次可以回答"哪些事被反复想做却没做成"，并据此配置支持资源。

对校园文化的价值

它传递的是一种态度：未完成不等于失败。 一代人没做完的事，可以被下一代人接住——这本身就是在校园里培育一种可持续的善意循环。

6.2 未来展望

方向设想
跨校传承网络同一议题在不同高校间往往重复发生（如无障碍、旧物循环）。可打通校际种子库，让成熟经验跨校复用，而不是每所学校各自从零摸索。
组织级接入向团委、社团联合会提供议题洞察与传承健康度看板，把数据沉淀为决策依据。
智能体生态沉淀标准化技能，使不同类型项目（支教 / 调研 / 文创 / 工具开发）拥有各自的交接模板与匹配策略。
长期记忆让知颜记住一位同学跨越数年的成长轨迹，在他毕业时主动提醒"你三年前想做的事，现在有人可以接了"。

6.3 结语

一粒种子的凋零，从来不是故事的终点——它落进土里，便成为下一季的养分。

每一年，校园里都有人带着遗憾离开，也有人怀着热忱抵达。 「第五季」想做的，只是在这来去之间修一座小小的桥： 让善意被记得，让经验被传下，让每一个「如果当时」，都变成「幸好现在」。
